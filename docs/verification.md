## 功能覆盖

- 资料同步：首次绑定、三方冲突与备份、双 clone 收发、失败时保留本地提交、任务和交接记录、真实 autocrlf 克隆、缓存排除、静态技能资产及字节往返。
- 私有远端：上传与快捷同步前核验 GitHub 私有属性；公开、未知、重定向、不同 fetch/push 目标与 URL 改写均停止。快捷入口和调度要求程序、资料库及本机工作区相互独立，并在写入前拒绝与程序源码或其所在 Git 工作树重叠的直接绑定。
- 快捷同步：同 mtime 的内容变动、原技能硬链接按 inode 去重读取、只读 `--check`、手动与定时防重入、本地待推和远端新提交检测、冲突及独立镜像改动保留。
- Git 完整性：每轮实时核对未跟踪受管文件是否被忽略，覆盖本地、全局和嵌套 ignore 规则；快捷同步在落盘前检查预计写入文件，`git-sync` 在暂存前检查完整候选集合。被忽略资料不能成为已同步状态，不使用强制暂存；普通缓存仍排除。
- 快捷入口与调度：Windows/macOS 路径引用、生成物所有权、不覆盖用户文件、保留控制路径保护、中文结果、交互等待及非交互退出；默认每 60 分钟、周期修改与移除、系统定义读回、失败事务、日志保护与防重入。
- 后台进程：Windows Git、凭证查询和 Codex RPC 子进程使用隐藏窗口参数；真实隔离 RPC 握手、文本往返、超时与进程回收通过，原有管道、认证及错误脱敏行为有回归覆盖。
- 对话来源：显式清单、不可变归档、按来源去重、原始字节与哈希、Codex 分页读取、拒绝链接及越界来源、来源失败保留和只读检查不创建档案。

## 真实 Codex 接口

使用已安装的 Codex CLI **0.163.0**，两个独立测试资料目录和两个不同项目路径。模型端为仅监听 localhost 的确定性 Responses 测试服务，不发送真实用户聊天、凭证或外部模型请求。

1. 实际 app-server 创建测试线程并生成一轮固定问答；测试源显式使用 paginated 历史模式。
2. 产品代码通过公开 `thread/read`、`thread/turns/list`、`thread/items/list` 分页导出并归档。
3. 将档案复制到第二份测试资料目录，通过 `thread/start` 与 `thread/inject_items` 恢复两条文本消息。
4. 关闭恢复进程，另启 app-server，以新 ID `thread/resume` 后开始验证轮。本机 Responses 服务实际收到的上下文同时包含原测试问题与答案。

这证明该已安装版本的真实接口可跨独立资料目录恢复文本上下文，并在新进程续接；不属于两台物理设备验收或真实模型推理验证。注入可能不创建 UI 可见历史项，不能保证再次分页导出注入内容或完整原生会话无损往返。
